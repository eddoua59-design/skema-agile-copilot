### Le processus DSDM

Schéma du cycle de vie (en arc) : **Pré-projet → Faisabilité → Fondations → Développement évolutif → Déploiement → Post-projet.**

- Le **Développement évolutif** est une boucle itérative ; il alimente le **Déploiement** (Assembler → Revoir → Mettre en œuvre), avec des retours possibles du Déploiement vers le Développement évolutif.
- Le processus DSDM est utilisé pour construire le cycle de vie de *ce* projet : on configure DSDM dans son évolutivité et son formalisme.

<!-- diapo 32 -->
### Quelques mots sur Scrum… (« Non examinable »)

« Comment Scrum s'intègre-t-il dans le DSDM ? » — schéma classique de Scrum (crédit : Neon Rain Interactive / Agile for All) :

- Entrées : dirigeants, équipe, parties prenantes, clients, utilisateurs → **Product Owner**.
- **Product Backlog** (liste ordonnée : fonctionnalités, histoires…) → **Sprint Planning Meeting** (l'équipe sélectionne, en partant du haut, ce qu'elle peut s'engager à livrer à la fin du sprint) → **Sprint Backlog** (découpage en tâches).
- **Sprint** de 1 à 4 semaines ; **Daily Scrum** toutes les 24 heures ; burndown/burnup charts ; la date de fin de sprint et le livrable de l'équipe ne changent pas.
- **Sprint Review**, **Sprint Retrospective**, **travail terminé** (Finished Work) ; rôles : Product Owner, The Team, Scrum Master.

<!-- diapo 33 -->
### Scrum dans le processus DSDM

Même schéma du processus DSDM, avec un sprint Scrum (1-4 semaines, Daily Scrum toutes les 24 h) placé **à l'intérieur de la boucle de Développement évolutif** : une itération/Timebox DSDM peut être menée avec Scrum.
